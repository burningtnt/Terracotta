# macOS 自动安装说明

macOS 上 Terracotta 通过一个 tar.gz 压缩包分发，包内同时提供可直接运行的裸可执行文件与一个 `.pkg` 系统安装包。

Terracotta 提供该安装包的原因是 macOS 的本地网络权限问题：若直接运行裸可执行文件，陶瓦因为没有本地网络权限会无法找到房间或广播房间。

## 判断安装状态

启动器每次运行时应先判断陶瓦是否已就绪：

- 硬性前提：`/Applications/terracotta.app` 必须存在。该目录缺失时一律视为未安装，即使本地解包文件完好无损；
- 在此前提下，再检查本地解包目录：所有文件可读并通过 SHA-512 校验则视为就绪；本地文件失效但依赖目录下存在旧版本的残留目录，则视为存在旧版本；其余情况视为未安装。

处于就绪状态时直接进入启动流程；未安装或存在旧版本时走下文的安装流程，无需用户干预。新版本安装并成功启动一次后，启动器应清理依赖目录中残留的旧版本目录。

## 安装流程

第一步是解包：把 tar.gz 解压到启动器依赖目录下，逐文件做 SHA-512 校验并恢复权限；任何一步失败都应删除整个版本目录，避免残留半成品。

第二步是系统级安装。先把 `.pkg` 复制到启动器用户目录下一个临时目录中，并转换成规范真实路径（解析符号链接，避免 macOS 上 `/var` 与 `/private/var` 不一致导致 shell 引用失效），然后通过 osascript 以管理员权限调用系统 `installer`：

```bash
osascript -e 'do shell script "installer -pkg <pkg 的绝对路径> -target /" with prompt "<本地化提示语>" with administrator privileges'
```

由于 `installer` 需要管理员权限，此步必然弹出系统授权窗口，要求用户输入密码等获取权限。

授权弹窗中的提示语可随启动器界面语言本地化。

安装过程的输出建议实时写入启动器日志；安装结束后删除临时目录，`installer` 退出码非 0 时判定为安装失败。系统找不到 `osascript` 时（正常 macOS 均自带）同样直接判定安装失败。

## 启动核心

安装完成后无需再触碰 `.pkg`，直接运行解包出的裸可执行文件即可，参考 [API 文档](http-api.md)。
